# 进销存单证实训沙盘 · 文员后台

**在线地址：** https://blueevening.github.io/wyerpmn/

> **定位声明**
> 本项目是**独立实现的纯前端单据流程演练沙盘**，用于练习商贸企业文员的采购、销售、出入库、退货、盘点、报表等单据流转。
> 与管家婆、任我行软件及其他任何商业 ERP **无任何关联，非其官方产品或授权演示**。
> 页面中的公司、往来单位、商品、金额均为**虚构演示数据**，不代表任何真实企业。
> 技术栈为单页 HTML + 原生 JS，数据仅存本机浏览器 localStorage，**不是企业级 ERP，不能用于真实记账**。

## 这套东西证明什么

不证明「我会操作某个商业 ERP 的正版软件」，而是证明：

- 理解**进销存单据流转**：采购订单→审核→入库、销售订单→审核→出库、退货回加、盘点差异入账、红冲回退；
- 理解**账实一致**：库存必须与出入库流水累计对得上；盘点差异按确认时账面重算，而不是按建单时快照；
- 理解**文员权限边界**：只能录入、查询、导出，不能财务审核、成本结转、凭证记账、直接改库存；
- 具备前端实现能力：状态管理、表单校验、乐观锁冲突拦截、备份校验与回滚、移动端适配。

## 使用方法

1. 双击打开 `index.html`（Chrome / Edge），或直接访问在线地址
2. 首次进入会显示右下角 **分步教程**，点【下一步】跟着练（共 23 步，覆盖建档、采购审核入库、销售审核出库、退货、盘点、备份、报表）
3. 想重看教程：点左侧菜单最底部的【分步教程】按钮
4. 二级页面底部都有【返回列表】/【返回工作台】
5. 快捷键：`Ctrl+S` 保存草稿、`/` 聚焦当前页搜索框、`Esc` 关闭弹窗/返回
6. 数据只存本机浏览器；侧栏【数据安全】提供整库备份导出 / 导入 / 历史备份 / 恢复最近备份。导入前会自动体检并快照，写入失败自动回滚；换电脑或清缓存前请先导出。

## 配套练习指令（按顺序做）

1. **建档**：左侧「基础资料 → 商品档案」点【+ 新增商品】，编码 `SP001`、品名 `原味花生`、单位 `包`、分类 `农副食品`，【保存】。再新增供应商，编码 `GYS001`、名称 `南宁桂味食品批发部`。
2. **录采购单**：采购订单 → 新增 → 选供应商 → 添加行（原味花生，数量 100，单价 4.5）→【保存并提交审核】→ 列表点【审核】→ 详情页【模拟仓管入库】。
3. **录销售单**：销售订单 → 新增 → 选客户 → 添加行（原味花生，数量 20，单价 6.0）→【保存并提交审核】→【审核】→【模拟仓管出库】。
4. **查库存**：实时库存搜 `花生`；再切「库存预警」看标红的低库存商品。
5. **查流水**：出入库流水 → 选起止日期 →【查询】→ 核对单据号 →【导出】。
6. **出报表**：业务报表 → 客户销售明细表 → 选近一月 →【预览】→【导出CSV】。
7. **做退货**：销售退货 → 新增 → 选已出库单 → 填退货数量 →【提交待审】→【模拟仓管确认（库存回加）】。
8. **做盘点**：盘点单 → 新增 → 选商品 → 实盘数填一个与账面不同的数 →【提交待审】→【模拟仓管确认（差异入账）】。
9. **进销存汇总**：报表中心 → 进销存汇总 → 选起止日期 →【查询】→【导出 CSV】。
10. **做备份**：数据安全 → 导出整库备份下载 JSON。

## 实训任务卡 L1–L6 判定规则

- **L1** 自己新增并保存 1 个商品 + 1 个供应商
- **L2** 采购提交 →【模拟财务审核】→【模拟仓管入库】，库存与流水生成
- **L3** 销售提交 →【模拟财务审核】→【模拟仓管出库】，库存扣减
- **L4** 退货提交后【模拟仓管确认】并成功回加/扣减库存
- **L5** 盘点提交后【模拟仓管确认】，按**确认时账面**重算差异并入账
- **L6** 在「进销存汇总」点【导出 CSV】

> 说明：进度记在本机 localStorage 的 `flags.tasks` 里，属**自我练习记录**，不是考核凭证，也不可作为能力证明。

## 技术说明

- 文件：`index.html` + `app.js`（约 6000 行）+ `styles.css`，无构建、无第三方依赖
- 数据层：单一 localStorage 键 `gjp-erp-clerk-v1`，`rev` 乐观锁防多标签互覆盖，损坏数据不覆盖原值并提供恢复条
- 金额：`Number` + `round2`，仅满足演示精度；真实财务系统应用整数分或 Decimal
- 已知限制：localStorage 约 5MB 上限、清缓存即丢、无登录与真实分权、无服务端并发控制
